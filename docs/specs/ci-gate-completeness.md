  `ci-gate` (job name "CI Gate") is THE single required branch-protection status check on `develop`/`main`. New CI jobs that must be required must be added to `ci-gate.needs`, never wired directly into branch protection — this prevents the matrix-rename fragility class (DEC-096/DEC-097). `ci-gate`'s pass/fail decision is fail-closed (`scripts/check-ci-gate.sh`, S-CIGATE-2): every job in `needs` must report `success`, except jobs named in the script's `ALLOWED_SKIPS` allowlist (currently EMPTY — cycle-006's sharded mutation gate replaced the skip-tolerant `mutants` job with `mutants-aggregate`, which runs `if: always()` with an internal Step-0 no-op and therefore never reports `skipped` to GitHub Actions; no `ci-gate.needs` member currently needs skip-tolerance), which may additionally report `skipped` — any other result (including a future GitHub Actions conclusion type never seen before) fails the gate by default. A job added to `ci-gate.needs` that can legitimately report `skipped` (e.g. a future PR-only or repo-variable-gated job) must ALSO be added to `ALLOWED_SKIPS`, or the gate will correctly start failing that job's push-event runs — enforced by the script's fail-closed default, not by convention alone. `ALLOWED_SKIPS` membership by itself is NOT the trust boundary.
